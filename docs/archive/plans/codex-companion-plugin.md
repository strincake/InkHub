# Codex 工作搭子插件迁移计划

目标：把现有 local-pet 的实际功能迁入 screen-scheduler 仓库内的独立 API 1 插件；设备连接、调度、画面与提示音传输由宿主统一管理。

## 范围与接口

- 源码位于 `plugins/codex-companion/`，只依赖 Python 标准库、Pillow 与宿主 `screen_plugin` API。不依赖旧 exe、旧 HTTP 服务或相邻工程。
- 保留 Codex 主会话跟随、异步询问等待/恢复、子代理过滤、增量扫描、过期待确认、最多四项一页的稳定列表、上下选择/翻页、确认自动跟随、原宠物及最新居中布局。
- 主页显示任务和设置，提供状态演示、翻页、提示音试听。通用 Agent/审批事件通过本机 JSON 收件目录接入，附命令行工具，不安装 Hook。
- 新增宿主通用 `ctx.play_wav(wav_bytes_or_path, volume=...)`：16 kHz / 单声道 / PCM16，最多 3 秒。插件每次最多一个声音请求。声音只能随当前显示版本播放，切换、过期或禁用后丢弃；模拟结果与真实回执分开，未知结果/失败停止自动发送。
- 提示音默认关闭；保留等待双音和完成三音，仅真实状态变化且近期有效时提醒，不在重放历史或心跳时重复播放。
- 录音不保存、不上传；宿主消费录音事件并暂停媒体，录音结束后继续调度。
- 不读取或修改旧运行配置，不启用实机，不抢占现有设备；新插件默认禁用。交付新宿主构建及插件 ZIP。

## 实现与验证

1. 宿主音频：扩展 Context/worker 输出、校验、串行媒体发送、音频回执和录音暂停；添加协议模拟器测试与文档。
2. 插件领域层：移植 metadata watcher、任务模型、事件收件箱和 CLI；用合成会话验证等待/恢复、分页、过期、隐私、幂等及重启。
3. 插件集成：原布局/宠物绘图、触发与动画/声音去重、自包含主页、manifest、README 与许可。
4. 验证：单元测试、真实 plugin_worker 子进程、安装/启用/设置/按键/禁用/重启/导出全流程、宿主回归、400×300 渲染人工检查；打包仅源码与静态资源。

## 独立分工

- 宿主音频与其测试/文档由独立工作单元负责，仅修改宿主公共文件。
- watcher/model/inbox 由独立工作单元负责，仅修改插件 `companion_core.py`、`report.py` 和相应测试。
- 入口/画面/主页/集成测试和最终复核由主工作单元负责。

验收以可安装、可独立运行、无旧服务依赖及本机模拟器实测为准；不将模拟显示/音频当作实体屏幕/听感验证。
