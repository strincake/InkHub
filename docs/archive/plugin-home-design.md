# 插件主页与设置入口改版设计 · 墨枢 InkHub

本文件记录本次改版的设计。代码、`PLUGIN_DEVELOPMENT.md`、README、示例插件和浏览器验证脚本已按此实现：专属页面独立显示，宿主表单按字段选择展示。

## 设置的定义

插件设置的展示方式由开发者根据能力复杂程度选择：简单配置适合使用墨枢自动生成的表单；复杂交互适合使用插件专属 UI。无需为同一组设置实现两套界面，也不强制两种方式互斥。插件可以把不同设置分布在两个入口，确有需要时也可在两个入口操作同一字段。

配置字段声明用于默认值、类型与范围校验，不等于必须展示一个宿主表单。无论从哪个入口保存，均使用同一份插件配置和同一套校验规则。

## 插件主页

插件专属页面统一称为“插件主页”。它是与屏幕总览、内容来源、插件中心和切换记录同级的主内容页面，不再嵌在设置弹窗里。

主页可以承载实际工作内容，例如便签编辑、相册列表、运行状态和手动操作；也可按需承载部分或全部设置。插件也可让主页只负责工作内容，把设置交给墨枢表单。

插件主页采用现有页面的主内容区宽度，并获得随视口伸展的高度；窄屏时允许内容正常滚动。宿主保留侧栏和页面标题，插件管理主页内部布局。继续使用隔离 iframe 和现有受限消息桥接，页面同级不改变其权限范围。

## 侧栏与入口

在当前“工作空间”全部导航项之后、底部本机运行信息之前，增加“插件”类目。声明主页的已安装插件在此注入自己的导航标题；默认使用插件名称，并允许开发者提供更适合用户阅读的短标题。

只有声明主页的插件才注入入口。禁用插件仍可进入主页查看状态、编辑配置；运行操作继续遵守启用状态检查。卸载插件后移除入口，若正在查看该主页则返回插件中心。

插件中心分别提供“打开主页”和“设置”入口：有主页时才显示前者，有交给宿主展示的设置字段时才显示后者。取消原来的“通用设置 / 插件专属页面”双标签。

## 清单约定

- `homepage`：可选、自包含 HTML 文件相对路径。
- `navigation_title`：可选侧栏标题，未填写时使用插件名称；需有主页才有实际作用。
- `settings`：继续定义所有需要宿主保存和校验的配置字段。
- `settings[].host_ui`：可选布尔值，默认 `true`。设为 `false` 时保留字段声明与校验，但不在墨枢设置表单中生成控件。
- `settings_page`：兼容旧插件，作为 `homepage` 的旧名称；两者同时声明时使用 `homepage`。新文档与示例统一使用 `homepage`。

以上字段命名和旧插件兼容方式是本次实施建议，并非用户指定的接口名称。旧插件可继续安装与运行，其旧专属设置页在独立主页中打开；是否保留宿主字段展示仍由 `host_ui` 控制。

## 三种常见组合

| 用途 | 插件主页 | 宿主设置 |
| --- | --- | --- |
| 简单后台生图 | 无需提供 | 展示简单配置 |
| 专属交互工具 | 工作内容及专属设置 | 可不展示任何字段 |
| 工作与配置分开 | 工作列表、状态和操作 | 展示相关配置 |

组合不是互斥枚举，不增加只能二选一的模式开关。

## 验收

1. 页面在主内容区打开，原导航仍可使用，侧栏插件入口位于现有类目下方。
2. 仅宿主设置、仅专属设置、主页工作内容搭配宿主设置均可使用，不强制重复配置。
3. 隐藏宿主控件的字段仍受类型、范围及未声明字段校验约束。
4. 切换主页、返回内置页面、卸载当前插件后，旧 iframe 的消息不能继续执行操作。
5. 保存配置、手动动作和执行状态推送保持可用；切换页面不触发设备连接或插件启用。
6. 示例、开发文档与浏览器检查使用相同的入口定义，并检查桌面和窄屏布局。
