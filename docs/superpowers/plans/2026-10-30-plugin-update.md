# 手动插件更新实施计划

**目标：** 沿用安装 ZIP 入口，按插件 ID 判断新增或更新；更新继承个人数据。

**实现：** Python 校验包并通过临时目录替换代码包，失败时回退旧目录；Rust 停止旧工作进程、迁移设置并恢复启用状态；现有安装对话框显示校验结果。

**约束：** 不增加界面入口；不比较版本大小，同版本可替换；保留 state、私有文件、显示规则、启用状态。新增设置取默认值，已移除设置不传给新插件，保留字段不兼容则拒绝更新。

## 实施与验证

- [x] Python：先添加包替换、残留文件清理、私有数据保留、无效包/ID 拒绝、替换失败回退、设置兼容性测试，观察失败；实现 `install_package(..., update_id=None)` 与 `merge_settings`，再运行测试。
- [x] Rust：在插件集成测试中覆盖安装接口自动更新、预检、新增/禁用/运行中插件、设置及私有文件保留、重启恢复。新增预检路由，安装路由按 ID 调用新增或替换，停用并等待旧工作进程退出后再替换。
- [x] 界面：现有对话框选包后预检，显示插件名称和新旧版本；确认按钮随结果变化；更新响应显示实际结果。
- [x] 执行 Python 单元测试、Cargo 测试和插件集成/浏览器检查；核对 diff 并更新插件文档。

## 重点边界

- 损坏或不兼容的 ZIP 不应中断旧插件。
- 更新不能混入旧包中已删除的代码文件。
- 启用中的旧进程不能在替换后继续写回旧状态。
- 禁用插件更新后仍禁用；更新不得运行其代码。
- 选择文件后再次更换或关闭对话框，旧预检响应不得覆盖新选择。

## 验证结果

- Python 单元测试：64 项通过；覆盖完整 ZIP 校验、文件/目录冲突、替换失败回退和数据保留。
- Cargo 工作区：32 项通过；新增 Windows 检查确认取消返回前旧进程已释放私有文件。
- 插件集成：19 项通过；多通道集成：9 项通过。
- 插件更新浏览器检查：4 项通过；通用界面检查：8 项通过。
- Debug 工作区构建通过。使用临时配置和模拟显示，未测试实体设备。
- 一次并行回归发生 Windows 临时访问拒绝；同项重跑通过，100 次连续代码包替换未复现。没有据此增加未证实原因的重试逻辑。
